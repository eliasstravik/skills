# Bitter-lesson litmus

A skill is admitted only when at least one candidate line encodes durable contingency rather than general competence.

## Survivor categories

| Category | Skill-worthy example |
| --- | --- |
| Private or internal facts | House schemas, internal field meanings, organization-specific data |
| Chosen-among-equals conventions | A selected naming scheme, directory contract, or approved workflow |
| Taste or quality bars | House voice, acceptance thresholds, review standards |
| Authority or approval structures | Who may decide, approve, waive, or escalate |
| Fresh local state | Current deployment facts, active ownership, volatile local configuration |
| Deterministic scripts or tools | Reusable operations whose code, not prose, is the durable asset |

One survivor category admits the proposal; it does not admit unrelated lines.

## Per-line test

Ask of every body line: “Could an agent with perfect reasoning and perfect public-world knowledge derive this?”

- `No` means the line may remain if it serves the SOP.
- `Yes` means delete it, even when it sounds useful or customary.

## Banned competence content

| Category | Derivable example |
| --- | --- |
| Public-tool how-to | “Use `git status` to inspect repository changes.” |
| Reasoning scaffold | “Break a complex problem into smaller steps.” |
| Generic best practice | “Write clearly and check your work.” |
| Current-model workaround | “Repeat the instruction because models often forget it.” |

Reject a proposal composed only of banned competence content. Do not rescue it by rephrasing, compressing, or moving it to a reference.
