# Copywriting

## Switch

Whenever any branch asks the user a question, never invoke `AskUserQuestion`; render each clear question directly in bold, put necessary context below it, then give numbered options whose first option is the recommendation and ends with `(Recommended)`.

First matching condition wins.

| Condition | Action |
| --- | --- |
| Fast or provisional request with no safety or integrity gap | Draft finished copy first from supplied evidence, label assumptions and proof gaps, and offer strategic alternatives only for concept, headline, subject, hook, offer, or CTA. |
| Weak positioning, unsupported scope, or offer logic would make polished copy misleading even with the supplied facts | Name the weakness, propose the smallest truthful correction, and wait; if rejected, draft provisionally with the unresolved risk visible. |
| Missing factual, audience, offer-detail, proof, capability, compliance, post-click, or source-use information would change the argument | Ask only the smallest questions needed before drafting, honoring no-browse and frozen-research limits. |
| Sufficient evidence remains | Draft complete commercial copy for the requested surface, preserving source facts, avoiding fabricated proof or claims, refusing living-writer imitation, and transforming distinctive customer language into brand-owned language unless direct reuse is authorized. |

## Details

- Before drafting or revising finished copy, read [clear commercial prose](references/clear-commercial-prose.md); use its revision loop and formula-equivalence check. If it is unavailable, preserve any supplied formula and revise toward ordinary, specific, testable language.
- Treat a supplied structure or formula as a semantic contract: keep its jobs, order, and relationships while changing the words for the product and audience.
- Put the reader's workflow and downstream result before implementation detail; name internals only when they help the buyer judge the product.
- Prefer the shortest headline that makes the outcome clear. Add pains, mechanisms, or qualifications only when they sharpen rather than bury the promise.
- Make calls to action name the specific next result or real product action, not a generic “learn more,” “get started,” or “install” when a clearer action exists.
- Treat distinctive customer phrases as evidence for pains, stakes, vocabulary, and objections, not as reusable public copy.
- Before drafting social, content, newsletter, or voice-led copy, translate customer language into brand-owned phrasing by changing exact wording, syntax, and metaphor while preserving the underlying meaning.
- Avoid close variants or swapped-noun jokes that preserve an unapproved customer metaphor; choose a fresh image from brand, product, or audience evidence instead.
- If brand samples and customer language conflict, follow brand evidence for public tone, use customer wording only in notes or source rationale, and state the voice assumption briefly after the copy.
