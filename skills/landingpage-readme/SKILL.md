# Landingpage README

## Recipe

1. Treat absence of `/copywriting` as terminal: respond only with `npx skills add /Users/eliasstravik/dev/skills --skill copywriting -g`.
2. Inspect the manifest, implementation, docs, current README, license, and visual assets before asking questions.
3. Derive the actor, useful behavior, first-success chain, requirements, commitments, proof, and visual availability from repository evidence.
4. Ask one unresolved consequential question at a time.
5. Invoke `/copywriting` with the evidence and approved replies for every audience-facing tagline, introduction, heading, and call to action.
6. Assemble a complete GFM README around the smallest truthful copy-pasteable path to first success and its immediate result or next action.
7. Reuse suitable existing visuals with accessible GitHub-safe markup.
8. Specify a missing visual as a marked placeholder with precise input → behavior → result production guidance.
9. Omit unverified proof and unstated compatibility, stability, maintenance, or support commitments.
10. Keep behavior-design methodology vocabulary out of every published field and comment.
11. Prepare the About description, focused topics, manual social-preview specification, and exact `gh` metadata commands.
12. Present the entire landing surface and proposed commands before any mutation.
13. Await explicit approval.
14. Write the approved README and social-preview specification.
15. Honor the approved metadata mode: live `gh` mutation only when authorized, exact saved commands otherwise.

## Details

- In normal flow, do not read or invoke `/copywriting` until repository inspection and gap resolution are complete; pass it the inspected evidence and approved replies.
- Ask about repository facts only when inspection leaves them consequentially unresolved; do not ask users to repeat an absent asset or unavailable proof already established by evidence.
- State the evidence-derived actor in the one-liner or opening paragraph near the project title.
